# 세면대 설치 확인 시스템 — Claude 작업 메모 (2026-11-21 기준)

새 Claude 세션이 같은 맥락으로 시작하도록 정리한 메모. 비밀번호·키·ID는 없다. 항상 한국어로, 짧고 과장 없이 답한다. 못 해본 테스트는 못 했다고 말한다.

## 목적
아기비데 온라인 출시(2026-11-20)에 맞춰, 고객이 자기 세면대 품번을 검색해 설치 가능 여부를 확인하게 한다. 운영자(김지수)가 관리 페이지에서 목록을 관리한다.

## 구성
- 고객 페이지 `index.html` (원본 `src/sink-head.html` + `src/sink-script.html`, 빌드 `node src/sink-build.js . vYYYY.MM.DD-n`)
- 관리 페이지 `admin.html` (직접 수정)
- 서버: Google Apps Script (코베 시트에 바인딩, clasp). 로컬 폴더 `event-gas` — `Code.js`, `Sink*.js`. 이 저장소엔 없다.
- 데이터: 별도 구글 시트 "베베노 세면대" (코베 시트 아님)
- 서버 `CODE_VERSION` 은 "122". 새 기능은 올려서 배포한다.

## 시트 탭 ("베베노 세면대")
- **세면대**: A 브랜드, B 품번, C 상태(가능/확인 필요/불가), D 메모(고객에게 안 보임), E 수정일시, F 수정자, G 제품 링크(직접 입력), H 고객 안내(고객 화면에 보임)
- **세면대 사이즈 DB** (14열): L 검토(보류/제외), M 링크, N 사진. 고객 검색에는 안 나오고 관리자 참고용.
- **세면대 확인요청**: 고객이 없는 품번을 검색하면 자동 기록
- **세면대 계정**: 관리자·스태프 계정 (개인정보 — 외부에 내용 공유 금지)
- **세면대 브랜드**, **변경 기록**(9열, H 되돌리기 정보 JSON, I 되돌림), **검색 기록**(A 일시, B 검색어, C 결과 수, D 첫 결과 품번, E 구분: 빈 칸=검색 / 방문 / 구매 클릭), **세면대 사진 보관**

## 고객 화면 원칙
- 전체 목록을 절대 넣지 않는다(경쟁사 유출 방지). 품번 4글자 이상 검색 → 앞부분 일치 최대 3개. `?q=품번` 으로 바로 검색 링크.
- 등록 안 된 품번은 "확인요청"으로 기록된다.
- 결과 카드: 브랜드·품번·상태·(있으면) 고객 안내 문구, "제품 정보 보기" 링크, "보러 가기" 버튼.
- 검색하면 주소가 `?q=` 로 바뀌어 뒤로 가기가 유지된다.

## 기능 이력 (최근)
- v116 사진 분류 묶음 저장 (`sinkSortBatch`)
- 사진 분류 카드: "비슷한 등록" 배지, 고객 안내 입력칸(△+안내 → "확인 필요"로 등록)
- 등록된 세면대에 **고객 안내** (수납장 때문에 지지봉 결합이 어려울 수 있음 같은 문구)
- **고객 검색 기록**(관리자 [고객 검색] 탭): 방문·검색·구매 클릭·결과 없음 요약, 날짜별 7일, 순위. 운영자 기기는 일부러 제외하지 않는다.
- 클릭 로그: `?sink=click&m=품번`, 방문 로그: `?sink=visit` (30분에 한 번)
- **기록 되돌리기** (v122): 관리자 [기록] 탭. v122 이후 변경만 가능.
  - 지원: 세면대 추가·수정·삭제, 사진 분류 일괄, 사이즈 DB 검토·링크
  - 되돌리기 JSON: `{del:[[브랜드,품번]], put:[{brand,model,st,memo,link,note}], rev:[{row,model,prev}], lnk:[{row,model,prev}]}`
  - 이미 되돌린 기록은 다시 못 한다. 관리자만 가능.
- 관리자 PC 화면 개편: ≥1000px 왼쪽 메뉴, ≥1400px 등록 칸 고정, 목록에서 고객 안내·메모 바로 수정(`.inl`)

## 서버 엔드포인트 (GET `/exec`, POST)
- GET `?sink=find` → items `[브랜드, 품번, 상태, 링크, 고객 안내]`, `?sink=visit`, `?sink=click&m=`, `?sink=admin&token=`
- POST 액션: `sinkSave`(note/memo/link 가 undefined면 유지), `sinkSortBatch`, `sinkSearchList`, `sinkLogList`, `sinkUndo`, `sinkSize*`, 계정·브랜드 관련
- 저장·삭제·되돌리기는 `sinkWithLock_` 로 잠근다.
- 캐시: `CacheService` 청크. `sink_index_v7`, `sink_size_v8`. 데이터가 바뀌면 캐시를 지운다.

## 배포 (서버)
`node --check` → `clasp push -f` → 기존 배포 ID로 `clasp deploy -i <ID> -d "설명"`. **새 배포를 만들면 주소가 깨진다.** 배포 후 `/exec` GET 으로 `alive` 확인(이 호출이 시트 서식·새 탭 생성도 한다).

## 배운 것 (같은 실수 반복 금지)
- **관리자 탭 추가 시 `showTab` 목록에 그 탭 id를 넣는다.** 빠뜨리면 탭이 빈 화면이 된다(고객 검색 탭에서 실제로 발생).
- 코드를 heredoc/`node -e` 로 생성하면 정규식 안의 `\r \n \t` 가 실제 줄바꿈이 되어 문법 오류가 난다. 서버 파일은 Edit 도구로 고치고 `node --check`. 오류가 있으면 clasp push 가 옛 코드를 그대로 배포한 것처럼 보일 수 있으니 반드시 확인.
- 화면 변경은 DOM 텍스트만 보지 말고 실제 보이는지(스크린샷)까지 확인한다.
- Pages 반영 1~3분. 확인은 `?v=숫자`.
- Apps Script는 접속자 IP를 못 읽는다. 권한 범위(Drive/ScriptApp 등)를 늘리면 재승인 전까지 웹 앱이 깨질 수 있다.
- 사이즈 DB에서 림 두께는 제조사 도면·상세에 거의 없다. 다시 찾으려 하지 않는다.
- 비밀 값을 꺼내는 통로(덤프 엔드포인트)는 만들지 않는다.

## 작업 방식 (사용자 선호)
- 추천만 하고 "만들어줘/해줘"를 받은 뒤 만든다. 묻지 않고 화면에 붙이지 않는다.
- "없애" = 완전 제거.
- 발송·송장·배송지연 같은 물류 기능은 제안하지 않는다.
- 로그인·비밀번호 입력은 사람이 직접 한다. 시트 비밀번호(B2)는 채팅에 적지 않는다.
- 고객 문구에서 효능을 단정하지 않는다(의료기기 관련).

## 아직 안 한 것
- 관리자 사이즈 DB·확인 요청·기록 탭은 예전 줄 모양 그대로(목록 개편은 세면대 목록만 함)
- "클릭이 너무 많음" — 어떤 작업을 줄일지 운영자에게 확인 필요
- 사진 분류에서 비슷한 품번 묶음 일괄 처리
- 자동 백업 (권한 범위 때문에 보류)
- 설치 가능 기준표(A6 카드) 초안은 있으나 쓰지 않을 가능성이 높다
